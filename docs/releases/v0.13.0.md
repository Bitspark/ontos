# ontos v0.13.0

**The first public release.** ontos was developed privately up to v0.12.0. This repository
starts its public history at v0.13.0, whose interface is that of the last private release, so
nothing a consumer calls changes. The one difference consumers will see is speed: the
TypeScript encoder now sizes its output once and writes a single buffer, about three times
faster on records made of many small values, with byte-for-byte the same output.

## What is published

| ecosystem | packages | install |
| --- | --- | --- |
| npm | `@bitspark/ontos-core`, `@bitspark/ontos-codec`, `@bitspark/ontos-data`, `@bitspark/ontos-data-json` | `npm install @bitspark/ontos-codec` |
| crates.io | `bitspark-ontos-core`, `bitspark-ontos-codec`, `bitspark-ontos-data`, `bitspark-ontos-data-json` | `cargo add bitspark-ontos-codec` |
| Go | `github.com/bitspark/ontos` (core, codec, data, data/json) and `github.com/bitspark/ontos/projection/deixis/go` | `go get github.com/bitspark/ontos@v0.13.0` |

The npm packages carry provenance from this repository's release workflow.

The Rust crates are published under `bitspark-` names, but their library names are the short
ones, so code reads `use ontos_core::Value;`. To keep that spelling in a manifest, name the
dependency by its library and point `package` at the crate:

```toml
ontos-core = { package = "bitspark-ontos-core", version = "0.13.0" }
```

Go modules are released by tag: `v0.13.0` for the root module, and
`projection/deixis/go/v0.13.0` for the projection module, both at the same commit.

## Not published yet

The **ontos-over-deixis projection** ships its Go face in this release. Its Rust crate is in the
repository but not on crates.io, and its TypeScript face is not in the repository yet. Both depend
on deixis packages that are not on crates.io and npm yet, and they follow once those are.

The Python implementations (`core/py`, `codec/py`, `data/py`, `cli/py`) are source-only, and the
command-line tools are built from source.

## What holds

- **The byte format is `ontos-codec-v1`, and it is frozen.** Every encoding produced by an earlier
  version is produced identically by this one, and any future change to the byte mapping ships as
  a new codec version, never as an edit to v1.
- **Four implementations, one set of bytes.** Go, Rust, TypeScript and Python are checked against
  the same conformance vectors (`vectors/`), and a differential harness runs all four
  command-line tools over them on every change. See `docs/spec/ontos-conformance.md`.
- **Limits are reported, not guessed.** A decoder stopped by an operational bound reports which
  bound, as `limit_kind` (`docs/spec/ontos-codec.md` §4.2).

The specifications are in `docs/spec/`.
