# `ontos-vector` — the maintainer vector generator

`tools/vector/gen.mjs` is a small Node ESM **maintainer tool** (not a consumer
tool) that derives the Class B (`map`/`set`) conformance vectors from their
human-authored source and cross-checks them against the pinned canonical vectors.

## What it is

The `map`/`set` byte forms are not hand-authored: their canonical entry/element
**order** is the `ontos-codec-v1` byte order over the key/element
([ontos-codec §6](../../docs/spec/ontos-codec.md),
[ontos-data §5.7–§5.8](../../docs/spec/ontos-data.md)), which is impractical to
hand-compute. So **authorship is split from derivation** — the conformance-vector
provenance policy. A maintainer hand-authors the *membership* of each `map`/`set`
in [`vectors/data.source.json`](../../vectors/data.source.json), in a deliberately
**non-canonical (reverse)** order plus an `order_explanation` (why the canonical
order is what it is, by codec bytes); this tool then **derives** the sorted
`value` + `hex` via `@bitspark/ontos-data`'s `encodeMap` / `encodeSet` (which
sort) and `@bitspark/ontos-codec`'s `encode`, writes the reviewed artifact
[`vectors/data.generated.json`](../../vectors/data.generated.json), and **asserts**
that every derived `{ value, hex }` reproduces the corresponding `map`/`set` case
in [`vectors/data.json`](../../vectors/data.json) byte-for-byte — exiting non-zero
on any mismatch. Because `data.json` is already pinned to all four encoders
(`go`/`rs`/`ts`/`py`), that reproduce-check IS the differential cross-check;
the oracle is the human-authored source plus the derivation rule, and the
committed generated bytes are a reviewed artifact, not the oracle itself. Full
policy:
[`docs/conformance-vector-provenance.md`](../../docs/conformance-vector-provenance.md).

## How to run

From the repo root, after building `core` + `codec` + `data` so the
`@bitspark/ontos-*` workspace packages resolve:

```sh
npm ci
npm run -w @bitspark/ontos-core  build
npm run -w @bitspark/ontos-codec build
npm run -w @bitspark/ontos-data  build

node tools/vector/gen.mjs
```

On success it rewrites `vectors/data.generated.json` and prints how many cases
reproduced `vectors/data.json`, exiting `0`. On any drift it prints the mismatch
and exits non-zero.

**If a case does not reproduce, fix `vectors/data.source.json` or this generator —
never edit `vectors/data.json`** (the cross-language tests depend on it
byte-for-byte; changing a `map`/`set` byte mapping is a codec-version concern, not
a vector edit).
