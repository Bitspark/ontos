# ontos v0.14.0

**The deixis projection in all three languages.** `ontos-over-deixis-v1`, the bridge between ontos
values and deixis trees, now publishes its TypeScript package and its Rust crate. Its Go face has
shipped since v0.13.0. The two new faces waited only for deixis to reach npmjs and crates.io.
Nothing else changes: every other package has the same API and the same bytes as in v0.13.0.

## What is new

| ecosystem | package | install |
| --- | --- | --- |
| npm | `@bitspark/ontos-deixis-projection` | `npm install @bitspark/ontos-deixis-projection` |
| crates.io | `bitspark-ontos-deixis-projection` | `cargo add bitspark-ontos-deixis-projection` |

```ts
import { project, recognize } from "@bitspark/ontos-deixis-projection";
const node = project(value);   // P: total
const back = recognize(node);  // R: partial, throws an Unrecognized refusal
```

```toml
ontos-deixis-projection = { package = "bitspark-ontos-deixis-projection", version = "0.14.0" }
```

Every face pins deixis at exactly `0.6.0`: κ, the key of a tuple's `i`-th child, must come from
the same deixis code in every face. All three faces pass the same vectors,
`projection/deixis/vectors/ontos-projection.json`. See `projection/deixis/README.md`.

## Also in this release

- **npm packages record their release commit (`gitHead`).** v0.13.0's did not, because the
  release publishes the packed tarball, and npm records a `gitHead` only from the manifest it
  publishes. The release workflow now writes it into each package before packing.

| Go | `github.com/bitspark/ontos` and `github.com/bitspark/ontos/projection/deixis/go`, by the tags `v0.14.0` and `projection/deixis/go/v0.14.0` |

The npm packages carry provenance from this repository's release workflow.

## What holds

- **The byte format is `ontos-codec-v1`, frozen.** No encoding changes between releases.
- **The projection is additive.** `ontos/core` has no deixis dependency. A consumer that imports
  `core`, `codec`, `data` or `data-json` gets none.
